The five read-only tools use the existing authenticated HTTP Hub. Input and output are validated; the serialized

## Validation and measurements

The HTTP integration fixture has one TypeScript file and one synthetic declaration. Its live host uses the actual
watcher, inventory, graph engine and query engine with a deterministic test extractor. After an immediate edit, ten
concurrent host requests trigger one extraction and return one consistent generation. Timeout, pause, stale reads,
verified checks, independent cancellation, input limits, traversal, prefix boundaries and BFS limits have regressions.
HTTP tests cover all five tools, an edit, a cached-tool call after opt-out and tool-list invalidation. Existing core
caller selection remains unchanged.

maximum **163.36 ms**. This meets the 200 ms target on this small fixture only; it is not evidence for large-checkout

## Implementation decisions

An unchanged metadata audit reuses the immutable graph and indexes, updating only the manifest checkpoint. This
prevents every query from repeating whole-graph resolution. Audits started concurrently are coalesced by the scheduler;
a late watcher event retries within the original two-second deadline. A reader timeout/cancellation never aborts the
shared build. Read-only instances expose their last saved snapshot only with explicit stale reads.
