## Determinism

Reversed record order and BOM + CRLF sources produce byte-identical `graph.json` and `MAP.md` (golden
`MAP.expected.md`). Cache keys and graph IDs contain no absolute paths, times or machine names. Linux only in this
session; the Windows run of the same unit suite is part of the release validation still open from stage 04.

## Packaged benchmark (Linux, headless, offline)

`tsx scripts/code-map-benchmark.ts <output> --only csharp-10000,fixture-10000 --runs 1 --idle-ms 0`. Packaged Electron
with `app.asar`, external grammar assets, empty `PATH`, blocked sockets/fetch. The C# grammar is loaded lazily from the
packaged resources on the first `.cs` file (this is the offline packaged C# smoke).

Cold phases (ms) — TS: enumerate 2,552 / parse 16,640 / resolve 4,366 / write 12,561. C#: enumerate 2,212 / parse
22,159 / resolve 7,592 / write 16,922. Source sizes: TS 4.6 MiB, C# 5.8 MiB, so map data is 28.6× and 46.4× the source.

**None of NFR-1, NFR-2, NFR-5 and NFR-6 is met on this machine.** The edit path re-enumerates, re-assembles and rewrites
the whole graph, walks the cache directory several times per publication and fsyncs every cache record; C# records
also carry lookup contexts and locals, which doubles cache size. These are the optimization targets of the next step.
The 4-thread container is slower than the Windows reference machine (TS fixture there: 37.6 s cold, 4.9 s edit p95), so
the two reports are not directly comparable.
