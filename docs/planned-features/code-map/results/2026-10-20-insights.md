# Code Map stage 10: Changes, Impact and checkout review

Date: 2026-10-20. Base revision: `6b7b5de`; implemented in the stage 10 commit containing this report.
Windows x64, Node 24.11.1; Docker Desktop Linux x64, Node 24.21.0, kernel 6.6.114.1-microsoft-standard-WSL2.
Electron 44.4.5. Existing `oxy-e2e:latest` / `oxy-code-map-work`; desktop Electron windows were never opened.

## Result

- Host-owned incoming impact for a symbol, a file or up to 500 changed paths. Cycles and visit/output caps apply;
  membership is excluded, heuristic edges require explicit opt-in. File impact projects original cross-file symbol
  evidence to its files. Its reverse index is lazy per generation and retains edge references rather than cloning
  the whole graph. Current deleted/excluded nodes are never synthesized.
- Visualizer Changes distinguishes changed files and potential dependents with shapes, explicit labels, colors and
  folder grouping. Impact offers depth 1–3 and states that potential dependents in indexed code are not exhaustive.
- The checkout selector chooses the main map or a registered Ensemble worktree. Switching resets history/positions;
  removed selections fail explicitly. Source navigation preserves checkout identity and the existing generation,
  hash, containment and span checks.
- Public Git comparison requires both `git.read` and `code-map.read`. Main authorizes registered checkout/task/base
  identities, including after asynchronous work and permission revocation; Workspace Host performs Git I/O. Main
  changes use the existing HEAD status checkpoint. Worktree changes include committed edits relative to stored
  `baseCommit`. `--relative` fixes tracked paths for project subfolders to match untracked paths.
- Git metadata is independently bounded to 500 files / 512 KiB, filters `.oxy` and retains rename old paths. More
  than 500 combined old/new impact roots is visibly truncated. Git and index checkpoints are independent; a refresh
  is required during continuing edits. Missing Git status is an error, not a clean result.
- Export is deliberately omitted (Could): the current iframe/public API has no save/export flow. No dependency or
  filesystem permission was added for it.
- Frozen 26-task offline corpus/harness, 6 training / 20 held-out tasks, seeded randomized paired attempts (at least
  three repetitions), metadata validation and analysis. No agent was invoked. See the
  [evaluation protocol](2026-10-20-agent-evaluation.md); benefit gate remains **unverified**.

## Failures encountered and resolved

- An active plugin's descriptor state is `active`, not just `enabled`; the first new Changes E2E correctly rejected
  the too-narrow check. Dispatch now uses the existing enabled-plugin registry and rechecks both permissions.
- A blanket source-tar `node_modules` exclusion omitted tracked fake CLIs. Copying
  `tests/fixtures/agents/node_modules` explicitly restored deterministic Ensemble tests. No real agent ran.
- The new test originally waited for an untouched draft to say Saved; the UI correctly said Draft. It now starts the
  created draft with an explicit brief. One launch without Xvfb failed before the subsequent headless pass.
- Initial Linux full check had 1 unrelated PTY failure (`kills the whole process tree`): the reused container's PID 1
  is `sleep infinity`, which leaves orphaned children as zombies. A temporary Python `PR_SET_CHILD_SUBREAPER` wrapper
  reaps grandchildren during validation; the entire check then passes, including this PTY test. No PTY product/test
  code was changed. Prefer `docker run --init` for future containers. The helper is recorded in the status file.

## Still open

This is functional validation on small fixtures, not a new performance/accuracy benchmark. Existing large-checkout
memory/throughput/disk targets, terminal p95 with visualization, packaged installer smoke, cross-platform determinism
and hosted Windows CI, actual external CLI sessions, accessibility review and dogfooding remain release gates. Paid
paired evaluation and later longitudinal learning evaluation are deferred to the owner. No measured savings or
release-readiness claims are made; Automatic learnings remains unavailable.
